# CSSX-A52 — Class map: named const exports, opt-in declarations

## Summary

- The generated `.map.js` is now **one `export const <camelCase> = "<emitted>";` per class**, in
  first-appearance order, with **no default export and no object literal**. Consumers import the
  binding directly (`import { contactPanel } from "./x.map.js"`, `class={contactPanel}`).
- Identifier edge cases are deterministic and never drop a class: `-`/`_` split + camelCase,
  invalid characters → `_`, digit-leading/reserved → `_` prefix, duplicate identifiers → `_2`,
  `_3`, … in first-authored order. Each adjustment is a XESSA4001 **warning** (previously collisions
  were a hard error and reserved/invalid exports were omitted).
- The `.map.d.ts` is **opt-in and default off** (`map-types: true` / `output.mapTypes: true`). When
  enabled it mirrors the JS exactly: one `export declare const <identifier>: "<emitted>";` per class,
  no `map` object and no default export. `emit-types` / `output.emitTypes` remains accepted as a
  deprecated alias.
- `map-name` / `map-dir` behavior is untouched.

## Edge-case rules (frozen in SPECIFICATION.md §8)

| Authored class | Identifier | Rule |
|---|---|---|
| `contact-panel` | `contactPanel` | interior `-`/`_` runs are separators |
| `panel_head` | `panelHead` | same rule for `_` |
| `__proto__` | `__proto__` | leading/trailing `_` runs preserved; a `const` binding has no prototype hazard |
| `2col` | `_2col` | digit-leading alias gets `_` |
| `default`, `delete` | `_default`, `_delete` | reserved word gets `_` |
| `foo.bar` | `foo_bar` | non-identifier characters become `_` |
| `foo-bar` + `fooBar` | `fooBar`, `fooBar_2` | first-authored keeps it; one XESSA4001 warning |
| `-` (no parts) | `_` | empty alias fallback |

Suffix allocation checks identifiers already emitted, so an earlier `fooBar_2` makes the next
collision `fooBar_3`. Empty class tables yield empty `.js` and `.d.ts` text (the CLI writes only when
the planner includes the artifact).

### Final map format (owner follow-up)

The CSS side-effect import was removed outright; there is no config flag for it. `import-css` /
`output.importCss` is no longer accepted by the compiler, CLI or extension. Style loading is the
page's responsibility (`<link>` or an explicit bundler `import "./x.css"`).

```js
// before
import "../styles/button.css";
export const button = "ui-button";
export const icon = "ui-icon";

// after
export const button = "ui-button";
export const icon = "ui-icon";
```

Compiler: `mapgen.ts` has no import line, `ClassMapOptions`/`PlannedOutput.importSpecifier` and
`output/importPath.ts` were removed, `emit-css: false` is valid on its own, and the class map is now
plain-Node importable. CLI/extension/config/fixtures/tests/benchmark pins were swept; consumer tests
import the generated CSS themselves where a bundler would.
